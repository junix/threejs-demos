threejs-demos 架构文档

一套由十二个精心构图的 WebGL 场景集合。透明 Alpha 渲染器 + 可复现的静态导出姿态，为视觉验证管线。面向科学可视化、生成雕塑与空间系统的速查参考库。

当前浏览器未启用 JavaScript，架构图将以静态方式展示。

产品概述

threejs-demos 是一个轻量级的 Three.js 场景演示集合。每个场景都是独立的纯前端可视化实验，覆盖天文轨道、地形、晶体、分子、城市、地球、飘带、晶格、向量场、纽结、粒子云、元球共十二个主题家族。每个场景均可通过 URL 查询参数 ?scene=<id> 切换，所有场景共享同一套渲染器、相机、光照与交互控制系统。

项目的核心设计目标有两个：一是提供可即开即用的透明画布场景（Alpha 通道），便于嵌入到其他页面或设计稿中作为素材；二是可复现的导出姿态——每个场景加载后相机角度固定，配合自动化截图管线生成一致的输出，可用于回归测试。

功能特性

12 个场景家族从天文到拓扑，覆盖多种可视化范式
Alpha 透明渲染透明画布，可直接叠加到任意背景
可复现姿态静态相机角度，截图一致
OrbitControls 交互鼠标拖拽旋转、缩放查看
Playwright 自动化无头浏览器截图 + 像素校验
TypeScript 类型完整类型检查，零运行时开销
Vite 构建极速开发 + 体验与生产构建
目录元数据catalog.json 记录用途、复杂度、标签

系统分层架构

图 1 · 系统分层架构

系统从上到下分为六层，自上而下为：浏览器运行时、场景家族、构建工具链、渲染测试管线、目录元数据、输出产物。各层职责单一，依赖方向自上而下调用，下层为上层提供能力。

浏览器运行时层负责在浏览器中加载并运行场景。index.html 是入口，main.ts 解析 URL 参数、创建 Three.js 渲染器、场景、相机与光照，然后调用对应场景函数填充场景内容，最后启动渲染循环并挂载 OrbitControls 交互。

场景家族层是项目的核心内容层。十二个独立的场景函数（orbital、terrain、crystal、molecule、city、globe、ribbons、lattice、vectors、knots、particles、metaballs）各自向同一个 root 组中添加几何体与材质。每个函数遵循相同约定：不接收参数，直接操作共享的根节点，完成后返回。

构建工具链层使用 Vite 作为开发服务器与生产构建工具，TypeScript 提供静态类型检查。package.json 中定义了 dev、build、render、test 等标准脚本。

渲染测试管线层是本项目的关键特色。capture.mjs 脚本驱动 Playwright 启动 Chrome（SwiftShader 软渲染），依次访问每个场景，等待 __VIS_READY__ 标志后截取透明背景 PNG，再用 pngjs 逐像素校验透明度、可见像素、彩色像素三项阈值，确保画面质量达标。

目录元数据层的 catalog.json 记录了每个场景的用途、所属家族、设计问题、复杂度与标签。它既是测试管线的输入（决定了要渲染哪些场景），也是文档索引的数据源。

输出产物层包含构建后的静态资源（dist/）、导出的透明 PNG（out/）以及像素统计报告。

主走查：渲染出图

图 2 · 端到端渲染出图流程
1
读取目录元数据 capture.mjs 读取 catalog.json，拿到 12 个场景的 ID 列表。若场景数量校验：若不足 12 个直接报错，确保参考库完整。
2
启动 Vite 开发服务器 用子进程启动 Vite，监听指定端口（默认 4173）。脚本通过 stdout 检测服务器就绪标志，超时则失败。
3
Playwright 驱动 Chrome 渲染场景 启动 Chrome（SwiftShader 软渲染，禁外网），每个场景打开一个新页面，访问 ?scene=<id>，等待 window.__VIS_READY__ 为 true。
4
截取透明 PNG 定位 #stage 画布元素截图，omitBackground: true 保留 Alpha 通道，输出到 out/<scene>-transparent.png。
5
交互契约验证 模拟鼠标移动事件，检查 __INTERACTION_COUNT__ 计数器递增，确保 OrbitControls 正常工作。
6
像素质量校验 pngjs 逐像素统计：透明像素占比 > 8%、可见像素 > 3.5%、彩色像素 > 2500。三项均达标才算通过。
7
输出产物与报告 12 张透明 PNG + 控制台打印每张的尺寸、透明率、可见率、彩色像素数。全部通过则测试通过。

场景渲染管线

图 3 · 单场景内部渲染管线

单个场景的渲染流程从 URL 参数解析开始，到画布输出结束，共经历以下阶段：

参数解析阶段。页面加载时，main.ts 读取 location.search 中的 scene 参数，默认为 orbital。如果参数不匹配任何已知场景，回退到默认值。

渲染器初始化阶段。创建 WebGLRenderer，开启 Alpha 透明通道、抗锯齿、 preserveDrawingBuffer（便于截图），设置 sRGB 色彩空间与 ACES 电影色调映射。

场景与光照阶段。创建 Scene、PerspectiveCamera（36° 视场角），添加半球光 + 方向主光 + 点光源边缘光三点布光。相机初始位置和角度固定，确保每次加载即出图一致。

场景构建阶段。调用对应场景函数（如 orbital()），函数内部创建几何体、材质、变换，全部挂到共享的 root 组上。每个场景函数都是纯构建器模式：不返回值，直接修改共享状态。

交互与渲染阶段。挂载 OrbitControls 绑定到画布，监听 change 事件触发重绘。首帧渲染后设置 window.__VIS_READY__ = true，标志场景就绪，供测试管线等待。

设计要点与约束

透明渲染约束

所有场景共享同一套渲染器配置（alpha: true、preserveDrawingBuffer: true、透明背景），确保输出 PNG 具备可用的 Alpha 通道。

可复现姿态

相机初始位置与角度固定，场景函数不依赖随机数或时间，保证每次加载画面完全一致。这是自动化截图测试的基础。

场景函数约定

每个场景函数都是零参数、无返回值，直接操作共享 root 组。这种统一接口让场景可以简单地按名称查找表调度，新增场景函数新增一个键值对映射。

离线像素校验

使用 SwiftShader 软渲染 + 外网阻断，保证测试环境与机器一致，避免 GPU 差异导致的像素波动。

单一入口单文件架构

所有 12 个场景在一个 main.ts，场景 demo 规模轻量，单文件管理更简单，场景间共享材质、颜色、工具函数也更方便。
